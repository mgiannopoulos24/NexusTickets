# NexusTickets

Πλατφόρμα διαχείρισης εκδηλώσεων και ηλεκτρονικών κρατήσεων εισιτηρίων, που αναπτύχθηκε ως υποχρεωτική εργασία για το μάθημα "Τεχνολογίες Εφαρμογών Διαδικτύου" (ΣΤ' εξάμηνο), Τμήμα Πληροφορικής και Τηλεπικοινωνιών.

## Επισκόπηση

Το NexusTickets είναι μια full-stack εφαρμογή ιστού που επιτρέπει στους διοργανωτές να δημιουργούν και να διαχειρίζονται εκδηλώσεις, στους συμμετέχοντες να πλοηγούνται και να κάνουν κρατήσεις εισιτηρίων, και στους διαχειριστές να εποπτεύουν την πλατφόρμα. Το σύστημα βασίζεται σε αρχιτεκτονική client-server και είναι προσβάσιμο αποκλειστικά μέσω του προγράμματος περιήγησης.

Η πλατφόρμα υποστηρίζει τέσσερις διαφορετικούς ρόλους: Διαχειριστής, Διοργανωτής, Συμμετέχων και Επισκέπτης. Η πρόσβαση στις λειτουργίες καθορίζεται σε επίπεδο API μέσω αυθεντικοποίησης JWT και εξουσιοδότησης βάσει ρόλου.

## Τεχνολογικό Πλαίσιο

### Νοτιαίο Άκρο (Backend)
- **Γλώσσα**: Go 1.22+
- **HTTP Framework**: Fiber v2
- **ORM**: GORM με PostgreSQL driver
- **Έγχυση Εξαρτήσεων**: Wire (compile-time)
- **Αυθεντικοποίηση**: JWT (ζεύγος access + refresh token)
- **Δομημένη Καταγραφή**: Zap

### Βάση Δεδομένων
- **Κύρια Αποθήκευση**: PostgreSQL 16
- **Cache / Αποθήκευση Συνεδριών**: Redis 7

### Μετωπιαίο Άκρο (Frontend)
- **Framework**: React 19
- **Εργαλείο Build**: Vite 8+
- **Διαχειριστής Πακέτων / Runtime**: Bun
- **Γλώσσα**: TypeScript 7 (strict mode)
- **Στυλιστική Διαμόρφωση**: Tailwind CSS v4
- **Στοιχεία Διεπαφής**: shadcn/ui (Radix primitives + Tailwind)
- **Εικονίδια**: Lucide React
- **Δρομολόγηση**: React Router v7
- **Διαχείριση Κατάστασης**: Redux Toolkit + RTK Query
- **Φόρμες**: React Hook Form + Zod
- **Διεθνοποίηση**: Ελληνικά / Αγγλικά, αρχεία YAML (`src/locales`), χωρίς βιβλιοθήκη
- **Χάρτες**: Leaflet / react-leaflet με OpenStreetMap και γεωκωδικοποίηση Nominatim
- **Δοκιμές**: Vitest + React Testing Library, Playwright για διαδρομές σε browser

## Εγκατάσταση για Τοπική Ανάπτυξη

### Προαπαιτούμενα

- Docker και Docker Compose
- Go 1.22+
- Bun 1.x
- Make
- [mkcert](https://github.com/FiloSottile/mkcert) (για τοπικά TLS πιστοποιητικά)

### Γρήγορη Εκκίνηση (Ανάπτυξη — Hot Reload)

```bash
# 1. Αντιγραφή template περιβάλλοντος και συμπλήρωση τιμών
cp .env.example .env

# 2. Δημιουργία τοπικών TLS πιστοποιητικών
make certs

# 3. Εκκίνηση όλων των υπηρεσιών (PostgreSQL, Redis, backend, frontend)
docker compose -f docker-compose.yml -f docker-compose.dev.yml up
```

Η εφαρμογή σερβίρεται στο `https://localhost:5173` (το Vite τερματίζει το TLS με το πιστοποιητικό mkcert και προωθεί `/api`, `/uploads` και το WebSocket στο backend).  
Το backend API είναι επίσης προσβάσιμο απευθείας στο `https://localhost:8080/api/v1`.

### Παραγωγική Διάταξη (Built SPA πίσω από nginx)

```bash
cp .env.example .env
make certs
docker compose up --build
```

Ανοίξτε `https://localhost`.

### Αρχικοποίηση Βάσης (Seed)

```bash
# Από τον host όσο το stack τρέχει:
cd backend && go run ./cmd/seed
```

Ο ενσωματωμένος διαχειριστής δημιουργείται αυτόματα στην πρώτη εκκίνηση του backend (`ADMIN_USERNAME` / `ADMIN_PASSWORD`, προεπιλογή `admin` / `ChangeMe123!`). Ο seeder προσθέτει τους δοκιμαστικούς `organizer` / `attendee` και δέκα ακόμη λογαριασμούς (ίδιος κωδικός), 7 κατηγορίες, 150 εκδηλώσεις με τύπους εισιτηρίων και 5 φωτογραφίες η καθεμία, καθώς και δείγματα κρατήσεων, μηνυμάτων και αιτημάτων υποστήριξης, και συμπληρώνει την καρτέλα «Διοργανωτής» κάθε εκδήλωσης από το προφίλ του διοργανωτή της (όνομα, πόλη, e-mail)· εκτελείται με `make seed`.

### Εκτέλεση Χωρίς Docker

```bash
# Backend
cd backend
go run ./cmd/server

# Frontend (ξεχωριστό terminal)
cd frontend
bun install
bun run dev
```

### Επαναφορά Βάσης

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml down -v
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d postgres redis
```

Όλα τα endpoints έχουν πρόθεμα `/api/v1/`. Η αυθεντικοποίηση χρησιμοποιεί Bearer tokens που περνούν στην κεφαλίδα `Authorization`.

```
POST   /api/v1/auth/register
POST   /api/v1/auth/login
POST   /api/v1/auth/refresh
GET    /api/v1/auth/username-available
GET    /api/v1/events
GET    /api/v1/events/search
GET    /api/v1/events/recommended
GET    /api/v1/events/:id
GET    /api/v1/categories
```

Όλα τα υπόλοιπα endpoints απαιτούν έγκυρο JWT και κατάλληλο ρόλο. Βλέπε `docs/api.md` για τον πλήρη χάρτη διαδρομών.

## Βασικά Χαρακτηριστικά

**Διαχείριση εκδηλώσεων**: Οι διοργανωτές δημιουργούν εκδηλώσεις με πολλαπλούς τύπους εισιτηρίων, έλεγχο χωρητικότητας, κατηγορίες, τοποθεσία και προαιρετικές συλλογές φωτογραφιών. Οι εκδηλώσεις ακολουθούν κύκλο ζωής: Πρόχειρο, Δημοσιευμένο, Ολοκληρωμένο, Ακυρωμένο. Η ακύρωση μιας εκδήλωσης ακυρώνει όλες τις κρατήσεις της και ειδοποιεί όσους είχαν κράτηση.

**Σύστημα κρατήσεων**: Η κράτηση δεσμεύει πρώτα τις θέσεις για 10 λεπτά (`pending`) και ο συμμετέχων στη συνέχεια την επιβεβαιώνει (`confirmed`). Η επιβεβαιωμένη κράτηση είναι οριστική· η υπαναχώρηση ή η λήξη της δέσμευσης την ακυρώνει και επιστρέφει αμέσως τις θέσεις. Η ατομική μείωση χωρητικότητας αποτρέπει την υπερκράτηση υπό ταυτόχρονα αιτήματα, και μια εργασία στο παρασκήνιο απελευθερώνει κάθε λεπτό τις δεσμεύσεις που έληξαν.

**Αναζήτηση**: Η αρχική σελίδα αναζητά κατά την πληκτρολόγηση και δείχνει έως τρία αποτελέσματα, με πλοήγηση από το πληκτρολόγιο. Η σελίδα εκδηλώσεων φιλτράρει ανά κατηγορία, τίτλο, ελεύθερο κείμενο, ημερομηνίες, τιμή και τοποθεσία. Κάθε λέξη αντιστοιχίζεται ως πρόθεμα, με την ελληνική αναζήτηση πλήρους κειμένου της PostgreSQL.

**Ανταλλαγή μηνυμάτων**: Διοργανωτές και συμμετέχοντες που συνδέονται με επιβεβαιωμένη κράτηση αλληλογραφούν μέσω εισερχομένων/απεσταλμένων, με ζωντανή παράδοση και ένδειξη μη αναγνωσμένων μέσω WebSocket. Ο διαχειριστής μπορεί επιπλέον να γράψει στον διοργανωτή κάθε εκδήλωσης που είναι ακόμη ανοιχτή για κρατήσεις. Η ακύρωση εκδήλωσης στέλνει μήνυμα σε όσους είχαν κράτηση.

**Σύστημα συστάσεων**: Οι συνδεδεμένοι χρήστες λαμβάνουν εξατομικευμένες προτάσεις από τις κρατήσεις τους και τις εκδηλώσεις που επισκέφθηκαν, μέσω μοντέλου Biased Matrix Factorization που εκπαιδεύεται περιοδικά. Νέοι χρήστες και επισκέπτες βλέπουν τις δημοφιλέστερες εκδηλώσεις.

**Εργαλεία διαχειριστή**: Ο διαχειριστής εγκρίνει ή απορρίπτει εγγραφές, διαχειρίζεται χρήστες και εκδηλώσεις, απαντά σε αιτήματα υποστήριξης και εξάγει τον πλήρη κατάλογο εκδηλώσεων σε XML ή JSON σύμφωνα με το DTD της εκφώνησης.

**Χάρτες**: Οι σελίδες εκδηλώσεων εμφανίζουν χάρτη OpenStreetMap. Χωρίς συντεταγμένες, εντοπίζεται η διεύθυνση της εκδήλωσης και η θέση σημειώνεται ως κατά προσέγγιση. Στις φόρμες εγγραφής, λογαριασμού και εκδήλωσης, η πληκτρολόγηση διεύθυνσης τοποθετεί την πινέζα, ενώ το κλικ στον χάρτη ή η μετακίνηση της πινέζας συμπληρώνει συντεταγμένες και διεύθυνση.
