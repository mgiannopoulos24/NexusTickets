## Εισαγωγή

Στόχος αυτής της εργασίας είναι η ανάπτυξη εφαρμογής διαχείρισης εκδηλώσεων και ηλεκτρονικών κρατήσεων. Η εφαρμογή αυτή θα υλοποιηθεί βάσει της αρχιτεκτονικής web browser / web server και κάθε χρήστης θα έχει πρόσβαση σε αυτή μέσω του προγράμματος περιήγησης παγκόσμιου ιστού.

Στην εφαρμογή υπάρχουν τέσσερις (4) ρόλοι:

- **Διαχειριστής Εφαρμογής** (Admin)
- **Διοργανωτής** (Organizer)
- **Συμμετέχων** (Attendee)
- **Επισκέπτης** (Guest)

Κάθε άτομο που εγγράφεται στην εφαρμογή μπορεί, με τον ρόλο του Διοργανωτή, να δημιουργήσει μία ή περισσότερες εκδηλώσεις στις οποίες μπορεί να γίνει κράτηση ή, με τον ρόλο του Συμμετέχοντα, να πλοηγηθεί/αναζητήσει εκδηλώσεις που έχουν δημιουργήσει άλλοι χρήστες προκειμένου να πραγματοποιήσει κρατήσεις.

Οι χρήστες που εισέρχονται στην υπηρεσία με τον ρόλο του Επισκέπτη μπορούν μόνο να πλοηγηθούν/αναζητήσουν εκδηλώσεις χωρίς να μπορούν να πραγματοποιούν κρατήσεις.

## Απαιτήσεις Εφαρμογής

### 1. Σελίδα Καλωσορίσματος (Welcome Page)

Η εφαρμογή θα στέλνει αρχικά στο πρόγραμμα περιήγησης (browser) του επισκέπτη μία σελίδα καλωσορίσματος (welcome page). Η σελίδα αυτή θα πρέπει να παρέχει τη δυνατότητα στον χρήστη να κάνει εγγραφή στην εφαρμογή πατώντας το αντίστοιχο κουμπί.

Επίσης, θα πρέπει να δίνει τη δυνατότητα εισόδου ενός χρήστη στην εφαρμογή δίνοντας το όνομα χρήστη (username) και τον κωδικό χρήστη (password). Όλες οι αλληλεπιδράσεις πρέπει να είναι κρυπτογραφημένες μέσω του πρωτοκόλλου SSL/TLS.

### 2. Εγγραφή Χρήστη

Η σελίδα εγγραφής ενός νέου χρήστη θα απαιτεί από αυτόν την εισαγωγή:

- Όνομα χρήστη (username)
- Κωδικό χρήστη (password)
- Επιβεβαίωση κωδικού χρήστη
- Όνομα (first name)
- Επώνυμο (last name)
- Διεύθυνση ηλεκτρονικού ταχυδρομείου (email)
- Τηλέφωνο επικοινωνίας
- Στοιχεία διεύθυνσης και γεωγραφικής τοποθεσίας
- ΑΦΜ (VAT Number)
- Όποια άλλα στοιχεία απαιτούνται

Αν το όνομα χρήστη χρησιμοποιείται ήδη από κάποιον άλλο χρήστη, η εφαρμογή θα πρέπει να τον προτρέπει να εισαγάγει ένα καινούργιο όνομα χρήστη.

Η επιτυχής εισαγωγή των στοιχείων θα οδηγεί τον καινούργιο χρήστη σε σελίδα που θα τον ενημερώνει ότι εκκρεμεί η έγκριση της αίτησης εγγραφής του στην εφαρμογή από τον διαχειριστή.

### 3. Διαχειριστής

Στην εφαρμογή θα υπάρχει ενσωματωμένος από την εγκατάσταση ένας χρήστης που θα κατέχει τον ρόλο του διαχειριστή. Όταν ο διαχειριστής εισάγει σωστά το όνομα του χρήστη που του αντιστοιχεί και τον κωδικό του, θα οδηγείται στη σελίδα διαχείρισης χρηστών.

### 4. Διαχείριση Χρηστών από Διαχειριστή

Μέσω της σελίδας διαχείρισης χρηστών ο διαχειριστής θα πρέπει κατ' ελάχιστο:

- Να πλοηγείται στη λίστα των χρηστών
- Να μπορεί από τη λίστα των χρηστών να πλοηγείται στη σελίδα των στοιχείων κάθε χρήστη
- Να εξετάζει τα στοιχεία των χρηστών
- Να εγκρίνει ή να απορρίπτει την αίτηση εγγραφής τους στο σύστημα αν πρόκειται για νέους χρήστες

### 5. Αρχική Σελίδα Χρήστη

Όταν εισέρχεται στην εφαρμογή ένας εγγεγραμμένος χρήστης θα πλοηγείται στην αρχική σελίδα της εφαρμογής.

### 6. Πλοήγηση από Αρχική Σελίδα

Από την αρχική σελίδα οι εγγεγραμμένοι χρήστες θα έχουν τη δυνατότητα να πλοηγηθούν στη σελίδα διαχείρισης εκδηλώσεων ή στη σελίδα πλοήγησης/αναζήτησης εκδηλώσεων.

### 7. Διαχείριση Εκδηλώσεων

Από τη σελίδα διαχείρισης εκδηλώσεων οι χρήστες θα μπορούν:

#### (α) Δημιουργία Νέας Εκδήλωσης

Οι πληροφορίες που περιλαμβάνονται σε μία εκδήλωση περιγράφονται από το ακόλουθο Document Type Definition (DTD):

```xml
<!ELEMENT Events (Event*)>
<!ELEMENT Event (Title, Category+, EventType, Venue, Address, City,
Country, GeoLocation?, StartDateTime, EndDateTime, Capacity,
TicketTypes, Bookings, Organizer, Status, Description, Media?)>
<!ATTLIST Event EventID CDATA #REQUIRED>
<!ELEMENT Title (#PCDATA)>
<!ELEMENT Category (#PCDATA)>
<!ELEMENT EventType (#PCDATA)>
<!ELEMENT Venue (#PCDATA)>
<!ELEMENT Address (#PCDATA)>
<!ELEMENT City (#PCDATA)>
<!ELEMENT Country (#PCDATA)>
<!ELEMENT GeoLocation EMPTY>
<!ATTLIST GeoLocation Latitude CDATA #REQUIRED Longitude CDATA #REQUIRED>
<!ELEMENT StartDateTime (#PCDATA)>
<!ELEMENT EndDateTime (#PCDATA)>
<!ELEMENT Capacity (#PCDATA)>
<!ELEMENT TicketTypes (TicketType+)>
<!ELEMENT TicketType (Name, Price, Quantity, Available)>
<!ATTLIST TicketType TicketTypeID CDATA #REQUIRED>
<!ELEMENT Name (#PCDATA)>
<!ELEMENT Price (#PCDATA)>
<!ELEMENT Quantity (#PCDATA)>
<!ELEMENT Available (#PCDATA)>
<!ELEMENT Bookings (Booking*)>
<!ELEMENT Booking (Attendee, Time, TicketTypeRef, NumberOfTickets,
TotalCost, BookingStatus)>
<!ATTLIST Booking BookingID CDATA #REQUIRED>
<!ELEMENT Attendee EMPTY>
<!ATTLIST Attendee UserID CDATA #REQUIRED>
<!ELEMENT Time (#PCDATA)>
<!ELEMENT TicketTypeRef (#PCDATA)>
<!ELEMENT NumberOfTickets (#PCDATA)>
<!ELEMENT TotalCost (#PCDATA)>
<!ELEMENT BookingStatus (#PCDATA)>
<!ELEMENT Organizer EMPTY>
<!ATTLIST Organizer UserID CDATA #REQUIRED>
<!ELEMENT Status (#PCDATA)>
<!ELEMENT Description (#PCDATA)>
<!ELEMENT Media (Photo*)>
<!ELEMENT Photo (#PCDATA)>
```

**Παράδειγμα XML:**

```xml
<Event EventID="EV1024">
  <Title>Συναυλία Σύγχρονης Μουσικής</Title>
  <Category>Music</Category>
  <Category>Live Performance</Category>
  <EventType>concert</EventType>
  <Venue>Θέατρο Πόλης</Venue>
  <Address>Λεωφόρος Κεντρική 25</Address>
  <City>Αθήνα</City>
  <Country>Greece</Country>
  <GeoLocation Latitude="37.9838" Longitude="23.7275"/>
  <StartDateTime>2025-07-12T20:30:00</StartDateTime>
  <EndDateTime>2025-07-12T23:00:00</EndDateTime>
  <Capacity>350</Capacity>
  <TicketTypes>
    <TicketType TicketTypeID="T1">
      <Name>General Admission</Name>
      <Price>18.00</Price>
      <Quantity>250</Quantity>
      <Available>180</Available>
    </TicketType>
    <TicketType TicketTypeID="T2">
      <Name>Student</Name>
      <Price>12.00</Price>
      <Quantity>100</Quantity>
      <Available>75</Available>
    </TicketType>
  </TicketTypes>
  <Bookings>
    <Booking BookingID="B501">
      <Attendee UserID="maria21"/>
      <Time>2025-06-20T11:42:10</Time>
      <TicketTypeRef>T1</TicketTypeRef>
      <NumberOfTickets>2</NumberOfTickets>
      <TotalCost>36.00</TotalCost>
      <BookingStatus>CONFIRMED</BookingStatus>
    </Booking>
  </Bookings>
  <Organizer UserID="org_athens_events"/>
  <Status>PUBLISHED</Status>
  <Description>Βραδιά με έργα σύγχρονων δημιουργών.</Description>
  <Media>
    <Photo>cover1.jpg</Photo>
    <Photo>hall.jpg</Photo>
  </Media>
</Event>
```

**Περιγραφή Στοιχείων:**

- **EventID:** μοναδικό id για την εκδήλωση
- **Title:** σύντομος τίτλος της εκδήλωσης
- **Category:** η κατηγορία στην οποία ανήκει η εκδήλωση (μπορεί σε πολλές)
- **EventType:** ο τύπος της εκδήλωσης
- **Venue/Address/City/Country:** πληροφορίες για τον χώρο διεξαγωγής
- **GeoLocation:** γεωγραφικές συντεταγμένες
- **StartDateTime/EndDateTime:** χρόνος έναρξης και λήξης
- **Capacity:** συνολική χωρητικότητα
- **TicketTypes/TicketType:** τύποι εισιτηρίων
- **Bookings/Booking:** κρατήσεις
- **Organizer:** ο διοργανωτής
- **Status:** κατάσταση (DRAFT, PUBLISHED, COMPLETED, CANCELLED)
- **Description:** πλήρης περιγραφή
- **Media/Photo:** φωτογραφίες

**Κανόνες Χωρητικότητας:**

- Το άθροισμα των ποσοτήτων όλων των τύπων εισιτηρίων δεν πρέπει να υπερβαίνει τη συνολική χωρητικότητα
- Να μην επιτρέπεται κράτηση όταν δεν υπάρχουν επαρκείς διαθέσιμες θέσεις

#### (β) Προβολή Ενεργών Εκδηλώσεων και Κρατήσεων

Να πλοηγηθούν στις ενεργές εκδηλώσεις που έχουν δημιουργήσει και να επισκοπήσουν τις κρατήσεις.

#### (γ) Τροποποίηση/Ακύρωση/Διαγραφή Εκδήλωσης

- **Διαγραφή:** επιτρέπεται μόνο πριν από τη δημοσίευση ή πριν από την πρώτη κράτηση
- **Ακύρωσ��:** ��φορά δημοσιευμένη εκδήλωση, μεταβάλλει την κατάσταση σε CANCELLED, δεν επιτρέπονται νέες κρατήσεις

#### (δ) Διαχείριση Χωρητικότητας

- Συνολική χωρητικότητα
- Διαθέσιμες θέσεις ανά τύπο εισιτηρίου
- Συνολικό πλήθος δεσμευμένων θέσεων

### 8. Πλοήγηση/Αναζήτηση Εκδηλώσεων

Οι χρήστες θα μπορούν να πλοηγούνται στις εκδηλώσεις βάσει:

- Κατηγορίας
- Τίτλου
- Περιγραφής (αναζήτηση ελεύθερου κειμένου)
- Χρονικού διαστήματος
- Τιμής εισιτηρίου
- Τοποθεσίας

### 9. Αναλυτικά Στοιχεία Εκδήλωσης και Κράτηση

Ο χρήστης θα μπορεί να προβάλλει τα αναλυτικότερα στοιχεία μιας εκδήλωσης και να πραγματοποιεί κράτηση.

**Απαιτήσεις:**

- OpenStreetMap για εμφάνιση γεωγραφικής τοποθεσίας
- Επιβεβαίωση κράτησης (δεν αναιρείται μετά την υποβολή)
- Έλεγχος διαθεσιμότητας εισιτηρίων
- Έλεγχος συνολικής χωρητικότητας
- Ενημέρωση διαθέσιμων εισιτηρίων μετά από κάθε κράτηση

### 10. Messaging

Μετά την πραγματοποίηση κράτησης θα δίνεται η δυνατότητα επικοινωνίας διοργανωτή-συμμετέχοντα μέσω σελίδας messaging:

- Κατάλογοι εισερχόμενων/απεσταλμένων
- Ένδειξη νέων μηνυμάτων
- Δυνατότητα διαγραφής μηνυμάτων
- Σε περίπτωση ακύρωσης εκδήλωσης: αποστολή ενημερωτικού μηνύματος προς όλους τους χρήστες με κράτηση

### 11. Επισκέπτες

Οι επισκέπτες θα μπορούν να πλοηγούνται και να αναζητούν εκδηλώσεις χωρίς να μπορούν να πραγματοποιούν κρατήσεις.

### 12. Εξαγωγή Δεδομένων (XML/JSON)

Ο διαχειριστής θα μπορεί να εξάγει τις εκδηλώσεις σε μορφή XML σύμφωνα με το DTD και σε αντίστοιχη μορφή JSON.

### 13. Αλγόριθμος Συστάσεων (Recommendation Engine)

Βάσει του ιστορικού των κρατήσεων και των εκδηλώσεων που έχει επισκεφτεί ο χρήστης, θα προβάλλονται προτεινόμενες εκδηλώσεις με τη χρήση αλγορίθμου **Biased Matrix Factorization (BMF)**.

**Τύπος:** R̂(u,i) = μ + b_u + b_i + P_u · Q_i^T

Για χρήστες χωρίς ιστορικό, ο αλγόριθμος λειτουργεί βάσει μόνο των εκδηλώσεων που έχει επισκεφθεί.

## Λοιπές Πληροφορίες

### 1. Ομάδες

Η εργασία είναι υποχρεωτική και πραγματοποιείται από ομάδες δύο (2) ατόμων. Το ποσοστό της επί του συνολικού βαθμού είναι 80%.

### 2. Έλεγχος Αντιγραφής

Οι εργασίες θα περάσουν από έλεγχο για αντιγραφή. Σε περίπτωση αντιγραφής, οι εργασίες μηδενίζονται.

### 3. Παράδοση

Η υποβολή θα περιλαμβάνει:

- Αρχείο .zip με τον πηγαίο κώδικα
- Αρχείο PDF με περιγραφή σχεδιαστικών αποφάσεων, παραδοχών και λεπτομερειών υλοποίησης

**Δομή αναφοράς PDF:**

- Εξώφυλλο (τίτλος, ονόματα ομάδας, αριθμοί μητρώου)

- Εισαγωγικό κεφάλαιο
- Υπόλοιπα κεφάλαια
- Επίλογος (δυσκολίες και τρόπος αντιμετώπισης)
